Gmail for Omarchy

Gmail, one account at a time.

Check Gmail from your Omarchy bar, read and reply in the experimental TUI, or use the structured agent CLI. Up to three accounts keep separate mail, permissions and Chrome profiles.

Three interfaces

Read-only by default. Write access only where you grant it.

The bar, terminal client and agent CLI share the same one to three accounts and keep them apart: separate lists, unread counts, credentials and Chrome profiles, with no combined Inbox. Sending and changing mail need a second, separate grant that you approve per account.

  • Omarchy bar

    Read-only

    Click the magma icon to see each account’s unread count and up to 30 recent Inbox messages with sender, subject, time and snippet. Activating a message or Open inbox opens Gmail in that account’s own Chrome profile.

    Refresh on demand, or turn on five-minute background refresh. The bar never sends mail, changes labels or read status, or saves mail to disk.

Terminal cache

Cached mail first. Gmail catches up.

The terminal client opens with the mail it already has and keeps it readable while Gmail refreshes in the background; a refresh requests only the changes since its last update. By default each account keeps its newest 2,000 messages within 256 MiB and evicts the oldest tail. An optional five-minute timer keeps the cache ready even while the TUI is closed.

Placeholder rows turn into messages as metadata and bodies arrive. A metadata 1/32 or bodies 1/32 counter reports the batch in progress, and scrolling past either end of the 32-row list moves continuously through adjacent cached mail.

Cached mail is private plaintext with owner-only permissions, kept apart from the bar’s memory-only snapshot.

Get started

Let your coding agent walk you through setup.

Point your coding agent at the repository or the complete release bundle and give it the prompt below. It downloads and verifies the release, installs the bar plugin and prepares private configuration, then guides you through Google Cloud Console one small step at a time, waiting for your feedback. You make the Google clicks and approve access in your own browser.

Setup promptRead-only bar

Read AGENTS.md and follow skills/omagma-setup/SKILL.md and docs/SETUP.md. Download and verify the latest complete Omagma bundle for my Linux architecture, then install its Omarchy bar plugin. Help me map my Gmail accounts to their existing Chrome profiles. Walk me through Google Console and OAuth one small step at a time, waiting for my feedback before the next Google step. Reuse my existing project and configuration where available, keep downloaded credentials private, and open consent in the correct profile for each account. Verify mail access and profile links, then give me launch and reconnect instructions.

Add your account addresses, each account’s Chrome profile directory, and whether you want five-minute background refresh. If you already downloaded the Google registration JSON, give its local path — never paste its contents or any tokens. For sending and mailbox changes in the terminal, use the full-access prompt.

What the Google part involves

  1. Your own Google project. Create a Google Cloud project, enable the Gmail API and configure the consent screen. Register Omagma with Google and keep its downloaded registration files private.
  2. One OAuth registration for the bar. A Google OAuth registration with gmail.readonly covers the bar and read-only terminal browsing.
  3. A second registration for writing. Full TUI and CLI access uses a separate Google OAuth registration in the same project, with gmail.modify and contacts (People API). The bar keeps its read-only grant.
  4. Consent per account, in its own profile. Each account maps to an existing Chrome profile. Consent opens there, and Omagma checks the returned address before storing the token in your Secret Service keyring.

While a Google app is in Testing, these grants expire after seven days; reconnecting is one command per account.

Prefer to set it up by hand?

  1. Download. Get the complete Linux x86_64 or arm64 bundle and its SHA256SUMS from the latest release.
  2. Install. Verify the checksum, extract, and add the widget to your bar. Installation guide
  3. Connect accounts. Create your Google OAuth registration, map each account to its Chrome profile and approve access. Account setup

Needs Omarchy’s Quickshell plugin host for the bar, Chrome, an unlocked Secret Service keyring with secret-tool, and system CA certificates; the TUI needs a UTF-8 terminal. Release bundles are static, so no Zig compiler is needed. arm64 backend builds are tested separately; ARM desktop integration has not been qualified.
