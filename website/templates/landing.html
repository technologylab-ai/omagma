Native terminal app · Linux and macOS

Gmail and Calendar in your terminal.

Omagma is a keyboard-first terminal client for Linux and macOS. Read and send Gmail, see the calendars of up to three Google accounts in one Week, create meetings with Google Meet, and join each call in the right Chrome profile.

Calendar

Plan the week, book the meeting, join the call.

Agenda, Day and Week views combine the calendars you choose from up to three accounts. Calendar is opt-in per account and uses its own Google permission.

01

Combined Week across three accounts

Show your own calendars, shared ones and subscriptions such as holidays, from one account or all three. Each event keeps its account, a source letter and the colour you picked, so the grid reads without colour too. Your choices persist across restarts.

Priority helps order a crowded hour. Non-declined events and new starts come first; +N counts what doesn’t fit, and Space lists every event in those hours.

Mail stays one account at a time. Calendar is the one place your accounts meet.

02

Create meetings with Contacts guests and Google Meet

Press n, choose the account and calendar, and set a timed or all-day event with its time zone. Pick guests from that account’s Contacts. Add Google Meet on calendars that support it, or paste an existing HTTPS meeting link.

Review before saving. The review lists the destination, time, guests and exactly who gets an email. Nothing is saved or sent until you confirm with y, a click, or Tab and Enter. Google generates the Meet link when the event is saved.

Reschedule with e. Edit events you organize, or one occurrence of a recurring series; guests, responses and the call stay attached. To change a whole series or an attendee copy, you can press b to open that event in Google Calendar.

03

Meeting reminders with Join in the right Chrome profile

While the TUI is open, a reminder appears over Mail or Calendar ten minutes before an event. It counts down to the start, then shows the time remaining during the meeting. Join opens the call in the Chrome profile configured for the event’s account, so a work call opens in your work profile.

Reminders wait while you compose or use your editor. Dismiss with a click, or M then Ctrl+D; ordinary typing never dismisses one.

04

Invitations in Mail, saved to Calendar

An invitation appears as a card inside the message. Review whether it adds, updates or cancels the event in Calendar. Accept or Tentative sends your RSVP and, with Calendar write permission, saves a supported invitation to Calendar.

Mail and Calendar results are reported separately, and checking an uncertain result never sends a second RSVP. Calendar and Follow-ups sit in the Mail sidebar.

Mail

Gmail in the TUI, one account at a time.

Each account keeps its own mailboxes, unread counts, credentials and Chrome profile. There is no combined Inbox.

  • Threads with the reader beside or below

    Vim keys and mouse. HTML mail renders as native text; scripts and remote images never load.

  • Search the cache or Gmail

    / searches cached mail and \ asks Gmail. Cached mail opens first while Gmail catches up in the background.

  • Markdown compose with preview

    Check the rendered message and its plain-text alternative, or hand the draft to $EDITOR. Replies keep the original context.

  • Send review with undo

    Sending needs an explicit confirmation, then an undo countdown you can cancel: ten seconds by default, configurable.

  • Attachments, labels and Contacts

    Attach and save files, archive, star and label mail, and edit the account’s contacts.

  • Follow-ups

    Set a local reminder on a message. Due follow-ups stay available offline and after restarting.

Beyond the TUI

Agent CLI, optional encrypted vault and the Omarchy bar

  • Agent CLI

    Experimental

    omagma cli

    The TUI’s account-scoped actions as JSON and JSONL for coding agents: mail, drafts, contacts, invitations and Calendar events. Account actions name their account explicitly.

    Discover it offline: omagma cli --help lists commands, and omagma cli --help calendar.event-review prints that command’s contract. Calendar writes go through review and apply with receipts; uncertain results are never retried automatically.

    CLI contract →

  • Encrypted vault

    Opt-in

    omagma vault migrate

    Keep cached mail, drafts, attachments, settings and account credentials in an encrypted vault. One unlocked omagma daemon serves the TUI and agent CLI, including over SSH.

    Without it, the cache is owner-only plaintext. Migrate explicitly, then activate the vault; only then are credentials stored there. Migration leaves your original files for you to retire.

    Vault setup →

  • Omarchy bar

    Read-only · Linux

    Omarchy / Quickshell

    Unread counts and up to 30 recent Inbox messages per account, in the Linux Omarchy bar. A message opens in that account’s Chrome profile.

    Mail only, no Calendar. The bar never sends, changes or saves mail to disk.

Permissions and privacy

Your Google project. Your consent, per account.

Omagma uses an OAuth registration in your own Google Cloud project. Each account approves its own access in its own Chrome profile.

Bar
gmail.readonly. Mail stays in memory.
Mail in TUI/CLI
Reading works with gmail.readonly. Sending and mailbox changes add gmail.modify; Contacts add contacts. If you also run the bar, give the terminal a separate registration so the bar’s read-only grant stays intact.
Calendar
Opt-in per account. calendar-write-owned creates and edits events on your calendars and saves invitations; add calendar-read for shared calendars and subscriptions. Generated Meet links need no extra permission.
Storage
Credentials use the default platform keyring (Secret Service on Linux, Keychain on macOS), owner-only unencrypted files you explicitly choose, or the vault after you explicitly migrate and activate it. The default mail cache is owner-only plaintext.
Testing apps
While your Google app is in Testing, grants expire after seven days; reconnecting is one command per account.

Get started

Let your coding agent walk you through setup.

Give your coding agent this website or the GitHub URL and the prompt below. It installs with Homebrew on macOS or downloads and verifies the matching Linux bundle, prepares private configuration, then guides you through Google Cloud Console one small step at a time. You make the Google clicks and approve access in your own browser.

Setup promptTUI + CLI · Linux or macOS

Read AGENTS.md at https://github.com/technologylab-ai/omagma/blob/main/AGENTS.md and fetch its linked setup workflow and account guide yourself. Follow skills/omagma-setup/SKILL.md, docs/SETUP.md and docs/CALENDAR-PERMISSIONS.md. Install the latest Omagma release for my platform: Homebrew on macOS, or the verified complete bundle for my Linux architecture. Set up the experimental terminal client and agent CLI with full Mail access, and ask me which accounts should also use Calendar and which Calendar capabilities I want. Help me map my Gmail accounts to their existing Chrome profiles. Walk me through Google Console and OAuth one small step at a time, waiting for my feedback before the next Google step. Reuse my existing project and configuration where available, keep any working read-only bar registration intact, keep downloaded credentials private, and open consent in the correct profile for each account. Verify mail and calendar access without sending invitations, then give me launch and reconnect instructions.

Add your account addresses, each account’s Chrome profile directory, and which accounts should use Calendar. If you already downloaded the Google registration JSON, give its local path; never paste its contents or any tokens. Only want the read-only Linux bar? Use the read-only bar prompt.

What the Google part involves

  1. Your own Google project. Create a Google Cloud project, enable the Gmail API (and the Calendar API if you want Calendar) and configure the consent screen. Keep the downloaded registration files private.
  2. Mail permissions. gmail.readonly covers the bar and read-only browsing. Full TUI/CLI Mail uses gmail.modify and contacts (People API). Alongside the bar, use a different registration in the same project and keep its read-only grant.
  3. Calendar, only where you want it. Add Calendar capabilities per account; calendar-write-owned covers creating events, Meet links and saving invitations. Calendar permissions
  4. Consent per account, in its own profile. Each account maps to an existing Chrome profile. Consent opens there, and Omagma checks the returned address before storing the token in your chosen credential store, by default Secret Service on Linux or your user Keychain on macOS.

While a Google app is in Testing, these grants expire after seven days; reconnecting is one command per account.

Prefer to set it up by hand?

  1. Choose your platform. On macOS, use brew install renerocksai/tap/omagma and the Mac guide. On Linux, get the complete x86_64 or arm64 bundle and its SHA256SUMS from the latest release.
  2. Install. Verify the Linux or manual Mac bundle. Add the widget only for a Linux bar installation; it also adds an Omagma launcher entry, and Super+Shift+E can open it instead of HEY. Installation guide · Keyboard shortcut
  3. Connect accounts. Create your Google OAuth registration, map each account to its Chrome profile and approve access. Add Calendar per account if you want it. Account setup · Calendar setup

Only the Linux bar needs Omarchy’s Quickshell plugin host. Live mail uses Chrome and the authorized credentials in your chosen store, by default the unlocked platform keyring; the TUI needs a UTF-8 terminal. Linux binaries are static musl, and Mac binaries use system libraries; no Zig compiler is needed to install either. Building from source needs Zig 0.17.0 exactly: see Development. arm64 backend builds are tested separately; ARM desktop integration has not been qualified.

Optional preview: omagma tui --fixtures shows fictional mail without contacting Google. It isn’t part of installation.
