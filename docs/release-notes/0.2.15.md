# Omagma 0.2.15

Google Drive delivery for outgoing files in the native TUI and agent CLI.

- **Choose how each file travels.** Keep a file attached, choose Auto to attach
  what fits, or share it from Drive. The TUI adds per-file delivery controls,
  Upload all and a confirmation when a selection exceeds attachment limits.
  Review the measured message plan before sending.
- **Restricted sharing.** Drive uploads are private and shared viewer-only
  with the final To and Cc recipients. Bcc with Drive is refused. Uploads and
  sharing start only during a confirmed send; saving, previewing and changing
  delivery perform no upload. Drive permission is separately authorized with
  the optional `drive-upload` capability.
- **Mixed CLI delivery.** Repeat and combine `--attach-file` and `--upload-file`,
  or use `--file` with `--attachment-mode attach|auto|drive`. `--dry-run` reports
  a metadata-only plan without importing, authorizing or contacting Google.
  Contextual command help and offline JSONL schemas describe the new choices.
- **Recover interrupted preparation.** Bounded progress and cancellation cover
  upload and sharing. Durable receipts preserve file IDs and confirmed or
  uncertain grants. Explicit preparation retries reuse the same operation;
  unknown Gmail submission is never automatically replayed. Editing, discarding
  or cancelling closes abandoned preparation without deleting uploaded files
  or revoking existing access.
- **A usage skill for agents.** The new `omagma` skill covers progressive CLI
  discovery, account scope, drafts, attachment delivery and receipt handling,
  alongside the existing installation and setup skill.
- **Check the running TUI.** `:version` reports the version compiled into that
  open TUI, even after the installed executable has been replaced. The command
  works offline and is listed in searchable help. Restart an open TUI after
  upgrading to load the replacement.
- **Calendar guests use the destination account.** The picker combines saved
  contacts with cached recent-mail recipients. An explicit Contacts search can
  reach beyond the initial contact list, and partial reads remain visible.
  Guests accept Mail-style display names and address lists, with duplicate
  addresses refused and only bare addresses submitted for review.
- **Keep the event interval when moving its start.** An untouched end follows
  start edits. After an end date, time or DST occurrence is explicitly edited,
  it stays fixed. The Calendar permission guide also preserves the selected
  backend, configuration, grant file and existing capabilities.

**Upgrading:** close running clients before replacing the executable; if you use
the encrypted vault, also run `omagma vault stop`. Then reopen Omagma.
All clients and the vault daemon must use
the same version for the new progress protocol. Existing accounts, drafts,
receipts and encryption settings are preserved. To use Drive delivery, enable
Drive API for the existing Google project and follow **Connect Drive** to add
the optional permission while retaining every existing terminal capability.
Ordinary attachment delivery requires no additional permission.

The **experimental** native app runs on Linux and macOS. The Omarchy bar remains
read-only; the browser version remains a tech demo with its existing scope.
