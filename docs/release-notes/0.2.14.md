# Omagma 0.2.14

More reliable invitation replies and Calendar updates in the native Gmail and
Google Calendar TUI and agent CLI.

- **Long Outlook and Teams invitations.** Calendar import accepts long folded
  descriptions within the existing complete invitation size budget. The
  separate Calendar parser no longer rejects an otherwise supported invitation
  because one unfolded line exceeds 4 KiB.
- **Check Calendar before sending an RSVP.** Accept and Tentative validate the
  Calendar action before submitting the response. A known blocker leaves the
  RSVP unsent and shows its reason. Retry after resolving it, review Calendar
  separately, or explicitly choose **s · Accept/Tentative without Calendar**.
  Repeating Accept never silently chooses the override. Decline remains
  email-only.
- **Recover without duplicate replies.** Mail and Calendar retain separate
  durable outcomes when a failure occurs after submission. **C · Check status**
  checks or retries Calendar without resending the RSVP, including invitations
  affected by the previous long-line failure. An explicit RSVP-only choice stays
  email-only across restarts and status checks.
- **The same policy in the CLI.** A known Calendar blocker returns
  `outcome:blocked`. Use `--rsvp-only` with `invitations reply`, or
  `rsvpOnly:true` in JSONL, to explicitly send only the response. The submitted
  choice is bound to its operation ID. Source identity, concurrent-client replay
  guards and Calendar storage admission are checked before sending. Settled
  RSVP-only receipts move to history instead of filling active draft slots.

**Upgrading:** close running clients and run `omagma vault stop` before replacing
the executable, then reopen Omagma. All clients and the vault daemon should use
the new version for the coordinated RSVP policy to take effect. Existing
accounts, drafts, receipts and encryption settings are preserved. No additional
Google permission is required for an RSVP-only response. Saving an invitation to
Calendar still requires its existing Calendar write permission; missing access
is now explained before an ordinary Accept or Tentative is sent.

The **experimental** native app runs on Linux and macOS. The Omarchy bar remains
read-only, and the bundled browser version remains a tech demo with its existing
feature scope.
