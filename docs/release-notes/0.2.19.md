# Omagma 0.2.19

Clearer CLI help for Google Meet AI notes, and personal calendar events from emailed ICS attachments.

- Correct the copyable Meet review and pending-command examples, including the event file and the single AI notes option.
- Explain the complete review, invitation, Meet settings confirmation and recovery workflow for agents.
- Resolve a person's current address from recent correspondence, and carry the agreed date, time zone and duration into the invitation.
- Exercise the printed Meet examples against disconnected providers, checking guest notifications, both AI settings, read-only reconciliation and duplicate protection.

- Import attendee-free published calendar attachments, including uppercase `.ICS` files labelled `text/plain`, through the existing review-and-confirm flow.
- Preserve all-day dates, notes and supported popup reminders; disclose unsupported alarms without sending RSVP mail.
- Accept valid tab whitespace in calendar data and names, quoted recipient and attachment names, and Markdown headings and lists.
- Read messages whose decoded Gmail Subject contains line breaks, and automatically retry previously cached header-decoding failures.

- Keep received mail readable when one header, address, part or character set is unusual: only that field or part is degraded, with a named notice in the reader, instead of the whole message being refused.
- Decode many more legacy character sets and mislabelled text, and keep oversized calendars and text parts as ordinary attachments.
- Re-read, once, every cached message that an earlier version had flagged or refused, so stale warnings disappear without clearing the cache.
- Show long or complex formatted mail up to the reader's limits with a notice, and remove blank-line gaps, tracking-pixel placeholders and invisible padding.
- Show invitations and Calendar views even when one property, event or calendar entry is malformed; replies and edits still require cleanly read data. Recognise Windows and prefixed time-zone names.
- Reply to mail with untidy threading headers, and keep replying available when one send-as alias is unusual.

- Mail: Esc steps back but never quits; the list always shows a short date, single-cell flags and, in Sent, the recipient; the reader header has aligned fields and coloured label chips with friendly names; triage notices name the action and offer Ctrl+Z; `n`/`N` jump between unread mail and `g` then `i`/`s`/`d`/`a`/`t` jumps between mailboxes, with the footer listing the choices while `g` waits; the `:` command line suggests the nearest command; Help opens with the essentials.
- Replies start with an "On <date>, <name> wrote:" line, and quoted text is escaped only where Markdown would otherwise change it.
- One footer style everywhere: keys in bold, labels muted, the least important hints dropped first on narrow terminals. The idle status row is empty.
- Calendar: one header row with view tabs, Monday-first weeks, working hours favoured in short terminals, agenda rows in columns with Today and Tomorrow headers and a "now" marker, `d`/`w`/`G`/`gg` navigation, lenient date and time entry (`fri`, `tomorrow`, `+3d`, `2pm`, `+45m`), and `c` to duplicate an event.
- Calendar Day and Week are a real calendar grid: events are coloured blocks sized by their duration on a time axis, overlapping events sit side by side (`+N` when a day runs out of room), all-day and multi-day events span a band above, today's column and current time are marked, and the working day is shown first with `Ctrl+E`/`Ctrl+Y` to scroll. Tentative, unanswered, declined and busy-only events stay distinguishable without colour.
- Calendar: delete an event (`D`) or answer an invitation (`r`) directly from the view or an event card. Each opens a dialog that reads the latest version, names the event, time and calendar, asks whether guests (or the organizer) get an email, offers this occurrence or the whole series (each with its own guests, answer and time), and changes nothing until `y`, which acts only on a dialog fully on screen for a moment, never on a typed-ahead key or a double click. Deletes and answers are conditional on the version shown, an attendee's delete only removes the event from their own calendar, and an unconfirmed outcome (also for a whole series, found from any of its occurrences) is checked with reads only, never re-sent by itself. Agents get the same through `calendar.event-delete-review` and `calendar.event-respond-review` with dry runs, and `event-apply` exits 6 for an unknown and 3 for a rejected outcome. A Calendar journal written by 0.2.19 is refused (not misread) by 0.2.18.
- Invitations say why they cannot be answered when their calendar data is damaged, and an invitation without a usable time zone can be added after you choose the zone in the review. A second identical RSVP is refused instead of re-sent.
- Agents: JSONL requests with unknown fields are refused instead of silently ignored, so a mistyped or unsupported option can no longer turn into a real send. `dryRun` is supported on sends, queueing and label changes. Errors name the field, the accepted values and a next step. `view:"summary"`, `fields` (reads only) and body options keep replies small; `mail.reply` accepts the note in one call; `draft.patch` edits a draft without dropping its recipients or threading. `omagma cli --help CMD` prints a compact card, `--manifest` lists every command, and exit codes distinguish rejected, not found, retryable and unknown outcomes.
