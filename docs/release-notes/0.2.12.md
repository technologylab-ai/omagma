# Omagma 0.2.12

Large replies and forwards can grow without running into the normal browsing
memory pool, including long conversations with accumulating inline images.

- **Expandable native compose memory.** Preparing, editing, saving, reopening,
  previewing and sending large messages, and continuing drafts in Gmail, use
  temporary memory sized for their actual content. Large operations may exceed
  256 MiB; ordinary browsing keeps its existing fixed pools.
- **Inline images retained once.** Private content blobs and streamed MIME
  replace repeated copies of embedded images. Final encoded message size is
  checked against Gmail's upload limit before submission.
- **Clearer protected-draft recovery.** An uncertain send keeps its original
  draft and receipt. The composer stays visible, explains where the draft is
  retained, and can open its saved HTML preview. Automatic resending and Gmail
  upload of an uncertain submission remain blocked.
- **Encrypted preview repair.** Saved previews from an unlocked vault open in
  the selected account's Chrome profile, with the private export bound to that
  vault and account.
- **Growing-thread regression coverage.** Tests exercise repeated replies near
  Gmail's message-size limit, hundreds of inline images, external-editor edits,
  saved-draft reopening, encrypted storage, restricted file descriptors and
  worker stacks, and interrupted submission recovery.

Close and reopen running Omagma clients after upgrading. Use the matching
version for clients sharing a private store. This update needs no additional
Google permission.

The experimental native Gmail and Google Calendar TUI and agent CLI run on
Linux and macOS, with an optional encrypted vault and daemon. The Omarchy bar
remains read-only; the bundled browser tech demo retains its existing scope.

See [memory ownership](https://github.com/technologylab-ai/omagma/blob/v0.2.12/docs/MEMORY.md)
and [terminal usage](https://github.com/technologylab-ai/omagma/blob/v0.2.12/docs/TERMINAL.md).
